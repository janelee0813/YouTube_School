# YOUTUBE CLASS

나답게 시작하고, 꾸준히 만드는 유튜브.

유튜브 수업 안내, 사전 질문, 교육 자료, 내 기록, 강사 답변, 관리자 편집을 체험하는 첫 번째 웹 버전입니다.

## 이번 버전의 범위

**2026-10-28 요청 변경에 따라 Supabase 작업을 제외했습니다.** GitHub → Vercel 배포가 목적입니다. 모든 데이터와 역할 선택은 **브라우저 localStorage 데모**입니다.

- 실제 로그인·회원 인증·서버 저장·이메일 초대는 없습니다.
- 데이터는 브라우저와 배포 도메인별로 저장됩니다. 다른 기기에는 동기화되지 않습니다.
- 데모 역할을 바꾸면 해당 역할의 화면이 표시되지만 **보안 경계가 아닙니다**. 브라우저 개발자 도구로 모든 데모 데이터를 읽거나 변경할 수 있습니다.
- 실명, 연락처, 실제 수강생 질문, 비공개 파일 등은 입력하지 마세요.
- Supabase 프로젝트, 연결 키, SQL, 유료 서비스는 만들지 않았습니다.

## 실행과 배포

Node.js 22 이상이 필요합니다.

```sh
npm ci
npm run dev
```

개발 주소: http://localhost:3000

```sh
npm run typecheck
npm test
npm run build
npm start
```

Vercel에서 `janelee0813/YouTube_School`을 Import하고 프레임워크를 **Next.js**, 루트 디렉터리를 `./`로 선택합니다. 추가 환경변수는 필요하지 않습니다. Production Branch는 `main`입니다. 이후 main 푸시 시 Vercel에서 자동 재배포됩니다.

## 데모 관리자 시작

1. 로그인 메뉴에서 **데모 관리자**를 선택합니다. 비밀번호는 없습니다.
2. 수업 콘텐츠 → 새 수업 → 제목·소개·목차·본문·준비사항을 입력합니다.
3. 상태를 `임시 저장`/`게시`/`비공개`로 선택하고 저장합니다. 미리보기로 입력 중인 내용을 확인할 수 있습니다.
4. 운영 회차에서 공통 수업을 선택하고 기수명·실제 일정·담당 강사를 설정합니다. 일정은 비워둘 수 있습니다.
5. 수강 권한에서 데모 수강생에게 운영 회차를 승인합니다.
6. 교육 자료에서 강의 노트, PDF, 실습지, 참고 링크 또는 영상 링크를 추가합니다.
7. 공지·설정에서 브랜드명과 실제 문의 채널을 관리합니다. 브랜드명은 `settings.brand` 한 곳에서 관리됩니다.

초기 수업에는 사용자가 제공한 목차만 포함되어 있습니다. 일정·연락처·강의 본문·네 가지 원칙·실제 파일은 임의로 만들지 않았습니다. 자료 구성안 세 개는 준비 중 표시이며 다운로드 버튼이 없습니다.

## 질문 흐름 확인

1. 데모 수강생 선택 → 첫 수업에서 질문 작성.
2. 임시 저장 후 내 기록 → 이어서 작성 → 제출.
3. 새로고침하거나 역할에서 나갔다가 다시 선택해도 기록이 유지됩니다.
4. 데모 강사 선택 → 질문 펼치기 → 답변, 내부 메모, 처리 상태 저장.
5. 같은 수강생으로 돌아가면 답변이 보입니다. 내부 메모는 수강생 화면에서 제외됩니다.
6. 답변 후 질문 수정 시 강사 화면에 `답변 이후 질문 수정됨` 표시.
7. 삭제한 질문은 일반 목록에서 숨겨지며 휴지통에서 복구할 수 있습니다.
8. 질문 폼 하단 `데모 저장 실패 체험`을 열어 다음 저장 실패를 설정할 수 있습니다. 실패 후 입력이 유지되며 다시 저장할 수 있습니다.

동일 질문 UUID를 재사용하고 저장 중 버튼 잠금·revision 검사·브라우저 Web Locks를 적용해 중복/동시 편집을 처리합니다. 이미 제출한 질문은 초안으로 되돌리지 않습니다.

## 데이터 구조와 코드

- `src/lib/types.ts`: Profile(사용자·역할), Course(공통 강의·목차), Cohort(기수·일정·담당 강사), Enrollment(수강 권한), Material(자료·파일), Question(질문·답변·상태·수정 버전), Note(내부 메모), Notice, Settings
- `src/lib/seed.ts`: 첫 수업과 데모 인물. 사용자 제공 콘텐츠와 데모 역할만 초기화합니다.
- `src/lib/validation.ts`: 입력 길이, URL 스킴, 게시 상태 등 Zod 검증
- `src/lib/demo.ts`: 순수 상태 변경 함수, UUID 중복 방지, 수정 버전 검사
- `src/lib/permissions.ts`: **데모 화면 표시용** 역할별 투영 함수. 실제 권한 보장 용도가 아닙니다.
- `src/components/provider.tsx`: 저장소 경계. 향후 API 저장소로 교체할 위치입니다.
- `src/components/admin.tsx`: 관리자 콘텐츠 관리
- `src/components/questions.tsx`: 질문·내 기록·강사 답변
- `src/app/globals.css`: 반응형 디자인, 키보드 포커스, 모션 감소 지원
- `tests/demo.test.ts`: 데이터 변경과 화면별 데이터 분리, 검증 규칙 테스트

저장 키는 `youtube-class-demo-v1`, 현재 데모 역할은 `yc-demo-role`, 첨부파일은 `yc-file-<path>`입니다. 파일당 2MB 제한이 있으며 브라우저 전체 저장 한도 초과 시 오류를 표시합니다. 앱 외부에 파일을 업로드하지 않습니다. 첨부 해제는 자료 연결만 제거하며 브라우저의 파일 값은 남을 수 있습니다. 초기화하려면 해당 배포 도메인의 사이트 데이터를 삭제하세요. 기존 데모 기록이 사라지므로 필요한 내용은 먼저 별도로 보관하세요.

## 후속 실제 서비스 연결

Supabase는 이번 요청에서 제외되었으므로, 다음 내용은 **미구현**입니다.

- 실제 회원 가입/로그인/초대 메일, 이메일 인증, 계정 복구
- 최초 관리자를 서버에서만 부여하는 절차
- 서버와 DB에서 수강 권한, 질문 소유권, 담당 강사 검증
- 비공개 파일 저장소, 짧게 만료되는 서명 다운로드 URL
- 여러 사용자/기기 사이에서 공유되는 영속 저장
- 실제 데이터베이스 RLS 및 접근 제어 통합 테스트

후속 단계에서는 Provider의 조회·변경·파일 처리를 인증된 서버 API로 교체하고, 위 관계를 DB 테이블로 옮깁니다. 클라이언트 역할 선택을 실제 권한으로 사용하면 안 됩니다. 관리자 권한·강사 배정은 신뢰할 수 있는 서버에서만 변경하며, 내부 메모는 질문 응답과 분리된 권한으로 저장해야 합니다. 비밀키는 서버 환경변수로만 관리합니다.
